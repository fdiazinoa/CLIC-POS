# Padrón de login y snapshots parciales

La respuesta de configuración fuera del alcance de usuarios puede contener bajas explícitas anexadas por el ERP. Tratar ese arreglo de tombstones como un padrón completo vaciaba la colección de usuarios y la pantalla de login.

La aplicación ahora distingue autoridad por colección según el alcance realmente solicitado: `users/pos_users` y `roles/pos_roles` son independientes. Fuera de ese alcance solo acepta bajas de usuario explícitas con ID y elimina exclusivamente esos IDs conocidos; una baja desconocida o repetida no cambia el padrón. Roles omitidos se conservan. Usuarios positivos o estructuras inválidas fuera de alcance producen error sin conceder autorización ni reemplazar los catálogos. Un snapshot completo de seguridad solicitado con usuarios vacíos sigue revocando a todos.

Las peticiones HTTP que solicitan usuarios o roles declaran ambos alcances explícitamente, conforme al contrato acoplado del ERP; los carriers parciales proporcionados conservan su alcance original. Las bajas de usuario se aplican antes de validar un catálogo de roles que puede revocar su rol. Los carriers completos explícitos sin opción de alcance conservan el contrato legacy; no se confunden con `master_scopes=none` inferido para peticiones V3 remotas. Los refrescos de seguridad completos/parciales se serializan por instancia, conservan recuperación de la cola tras rechazo y comprueban el guard de vinculación disponible dentro de la cola y antes de escribir. No hay fallback a usuarios demo, cambios de PIN, reglas de permisos, esquema, ventas, inventario o ERP.

Las pruebas ejecutan los métodos de producción de refresco estructurado y aplicación de seguridad: nueve usuarios y una baja ajena permanecen nueve; una baja existente solo retira uno; seguridad completa vacía revoca todos; aliases, scopes inválidos, ausencia de roles, concurrencia, guardas, rollback y recuperación posterior no resucitan usuarios revocados. También se ejecuta el método real del caller para verificar procedencia de scope. Falta confirmar el comportamiento en el POS físico tras actualizarlo; no se instaló ni publicó mediante esta implementación.
